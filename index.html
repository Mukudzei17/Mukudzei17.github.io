How I build

I don't write code. I build by directing AI: deciding exactly what the finished thing has to do, then working with the tools until it does.

  • I start from the end result. Before anything is built I know what a good answer, a good order form or a clean record looks like, so I can judge every draft against it.
  • I know when to push and when to stop. If an answer is vague or wrong, I send it back with a sharper brief or a different approach. When it meets the bar, I ship it.
  • I keep a person in the loop where it matters. Every build answers from checked sources, says where it got its answer, and hands anything uncertain to me.
  • I prove it with real numbers. Every figure on this page comes from the tools' own records, not estimates.

  1. The problem

    Before a large company signs, its security team sends a questionnaire. Where is our data stored? Who can see it? How is it protected? They routinely run to hundreds of questions, and every answer has to be right, because it can end up written into the contract.

    What I built

    An assistant salespeople use in Slack or in the Wordsmith app. It answers only from a library of about 49 security documents, and it names the document behind every answer. I wrote or rewrote the policies in it; the rest is the evidence behind them, like audit reports and certificates, which I collect, check and keep current.

    Paste in a few questions, or drop in the customer's whole questionnaire, and it comes back filled in, often with the supporting documents attached.

    How it works

    1. A salesperson asks a question or drops in the customer's file.
    2. The assistant searches the security library for the documents that answer it.
    3. It writes each answer, cites its source and fills in the file.
    4. I keep the library current, so every new answer reflects how things are today.

    What it has done

  3. The problem

    An order form is the contract a customer signs. Each one used to be assembled by hand from a template, one deal at a time, with its progress tracked in people's inboxes.

    What I built

    One standard order form, agreed with legal, and an assistant that fills it in. A salesperson pastes the link to the deal in the CRM, and the assistant copies across the customer's name, address, contact, plan and price, then lists anything it still needs. Typing "sent" logs the form, so legal can follow every negotiation from the first draft.

    How a salesperson uses it

    1. Move the deal to the contracting stage. A contract record is created automatically.
    2. Type in the agreed terms once.
    3. Paste the link to the assistant and get the draft back.
    4. Send it to the customer and type "sent" so it's tracked.
    5. Once it's signed, mark the contract active.

    What it has done

    ~90order forms requested in its first two months
    23salespeople using it

    2 June to 30 July 2026, counted in its Slack channel. From 2 June it became the standard way every new deal gets its order form, and in August it moved into the company-wide Wordsmith assistant.

  5. The idea

    A contract book is only trusted if every number in it can be traced to a signed document. I wanted ours to be exactly that, and to stay that way as new contracts land each month.

    What I did

    • Read every contract against its signed PDF, and cross-checked it with the previous version of the book and the CRM. New contracts are booked straight from the signed copy.
    • Flagged the handful without a clean signed copy for follow-up, so nothing in the book rests on an assumption.
    • Logged every change with its old and new value, so any figure can be traced.
    • Fixed the date logic so totals move only when someone updates the book, not every day the file is opened.
    • Wrote a rulebook, with a real example for each rule, so the next update is done exactly the same way.

    What it has done

    665contracts checked against their signed PDFs
    3sources reconciled for each one

    October 2026

    The rules, now written down

    • The signed contract is always the source of truth.
    • One exchange rate per currency, used everywhere.
    • A contract counts from the day it's signed.
    • New customers belong to the salesperson who won them, renewals to the account manager.
